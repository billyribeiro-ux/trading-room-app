### ANSWERED 2026-08-15 — owner statement

> "The original has v3, v4, and v5 of the app where the v5 has a message DO NOT TOUCH if you don't
> know what you're doing."

**They are versions of the APP.** That selects the second candidate — a different served bundle —
and rules out the media-stack and routing-tier readings. It is consistent with everything measured
above: the client we hold contains no version-switching logic because the switch chooses *which
client is served*, before it loads.

**The lead that makes this capturable rather than theoretical** is the one property in the bundle
that names a version, `full.js:1925`:

```js
roomV4Link = window.location.href.replace('.com/', '.com/v3/')
```

A `/v3/` URL **path prefix**. If each version is served under its own prefix, each bundle set can be
fetched and hashed directly.

`apps/room/scripts/collect-app-versions.js` does exactly that: it GETs `/`, `/v3/`, `/v4/` and
`/v5/`, hashes every script and stylesheet each index references, and compares them against the
SHA-256s in `apps/room/docs/source/README.md` so "which version do we already hold" is answered
rather than assumed. It is read-only, clicks nothing, and never touches the DON'T TOUCH block.

## The short answer

**`v5` is a per-room server-side switch, not a client feature.** It is a checkbox on the Manage Room
settings page (`sess.useV5`), hidden behind the collapsed "DON'T TOUCH" block, whose own warning says
it will not work unless PTR has cleared the account for it.

**The room bundle in this repository does not branch on it.** `useV5`, `useV3` and `useV4` appear
**zero** times in `apps/room/docs/source/main.d6d3c112b59b7d0d.js`. So whatever v5 selects, it is
selected *before* the client loads — the client we hold is one specific version and contains no
version-switching logic at all.

**This repository already reproduces the setting.** It is in the schema, in the type, rendered on the
settings page, and pinned by a 415-line contract test. What it does NOT do is *act* on it — it is
explicitly `wired: false`.

## What v5 changes

**Unknown, and the evidence in this repository cannot answer it.** Stated plainly rather than guessed.

What *is* established:

1. **The room client contains no v5 branch.** `useV5` / `useV3` / `useV4` occur **0 times** in
   `apps/room/docs/source/main.d6d3c112b59b7d0d.js` (2,887,876 bytes). Control: `sessData` matches in
   the same file by the same method, so the search read the file.
2. **It is therefore a server-side decision.** `onaftersave="saveSessField('useV5')"` persists it to
   the session record; nothing client-side reads it back.
3. **It sits among media-plane plumbing**, which is the strongest available hint at its domain. Its
   neighbours in the same block are `clusterID`, `backupClusterID`, `superClusterID`,
   `superClusterExpectedServerCount`, `useMediaMTX`, `mediaMTXClusterID`,

   `media_max_bitrate`, `media_fir_rate`, `media_relays`, `node_media_relays`,
   `node_ws_media_relays`, `generateRandomUDPPort`, `streamingThreads`
   (`ptr1-P22-settings-advanced-cluster.md:139-187`).

### The mechanism that probably serves a different version

The same block contains an **alternate-bundle override group**, introduced by this paragraph
(`ptr1-P22-settings-advanced-cluster.md:205`, shipped typos preserved):

> "These  vars allow to server altertaive code version for this room"

Its four fields (`ptr1-P22-settings-advanced-cluster.md:160-163`):

| label | bound to | helper (verbatim) |
| --- | --- | --- |
| Alt VendorJS | `sess.altCodeVendorJS` | `(name if alt vendorJS. ie. 'vendor2.min.js'` |
| Alt AppJS | `sess.altCodeAppJS` | `(name if alt vendorJS. ie. 'app2.min.js'` |
| Alt JanusJS | `sess.customJanus` | `(name if alt janusJS. ie. 'janus4.js'` |
| Alt Room.js | `sess.alt_roomjs` | `(name if alt Room.js. ie. 'RoomRemoteRec.js'` |

So the product **does** have a per-room "serve a different code version" facility, and it is a
separate, explicit one. Whether `useV5` drives the same loader or something else is **not
established** — do not assume it does.

**`customJanus` is worth noting on its own:** Janus is a different SFU from mediasoup. Its presence
implies the product has spanned more than one media stack, which is the kind of thing a "v3 / v5"
switch might select between. **This is a hypothesis, not a finding** — nothing read states it.
