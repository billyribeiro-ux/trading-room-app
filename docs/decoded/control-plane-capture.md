## ⚠ The capture file itself is NOT in this repository, and must not be

It contains **eight live HS256 JWTs** — 301 characters each, header, payload *and* signature — in
`panes.{apiKeys,badges,extraAdminUsers,sessions}.panel.html`. They arrive through the Launch anchor,
`ng-href="/session?id={{s.uuid}}&jwtSite={{tokSite}}"` (`views/page.welcome.html:379-381`), so every
serialised pane containing that anchor carried a usable site token. The payload also base64-encodes
the owner's name, email and user id.

**That is a defect in the collector, recorded here rather than quietly fixed.** The redaction masked
emails and 24-hex ids; a JWT is base64url, so it has no `@` and its segments are not hex, and it
walked through both. `.gitignore` already warned that captures contain *"in some cases a live JWT"*.
The warning existed and the script leaked one anyway, which is the argument for masking at CAPTURE
time rather than trusting whoever handles the file afterwards. Fixed in commit `4928f47`
(`maskJwt` + `maskTokenParams`, asserted against the raw serialised output).

**Everything in this document has been redacted**: JWTs, email addresses, 24-hex Mongo ids and any
query parameter whose name contains jwt/token/key/secret/sig/auth. Verified zero of each remain.

## The headline

**31 states are registered in this build. Not one of them is an operator surface.**

The census ran with three positive controls that all hit — `session` 20, `user` 61, `room` 33 — so
`census.trustworthy` is `true` and the zeros are real absence rather than a broken search. Of 20
operator-level terms swept across seven independent surfaces,
`verdict.operatorTermsInRouteRegistry` is `[]`.

The verdict the collector emitted, verbatim, and deliberately hedged:

> No operator-level term appears anywhere in the 31 states this build registers. On the
> application's own self-description, the control plane is not part of this bundle. This is stronger
> than the absence of a screenshot, and it is still a statement about THIS BUILD as served to THIS
> ACCOUNT — not proof that PTR operates without one.

This is what `docs/decoded/admin-surface.md` §D could not establish. §D searched captures taken as
one tenant owner and correctly said the control plane "cannot be matched, only designed" — but a DOM
capture cannot distinguish *there is no console* from *this account cannot see one*. A single-page
application must register every screen it can ever show at boot, before it knows who you are, so the
route registry separates the two. It contains only tenant-level states.

**The strongest single finding, and it is not the one above.** `states[*].data` is `null` on **all
31 states, with zero exceptions**. Not one route carries `requiresAuth`, a role, a permission tag or
a page title. **The legacy application expresses no authority whatsoever in its router.** Whatever
gates presenter and admin capability is decided on the server or inside a controller. There is no
route-level role model in the reference to copy, and looking for one is wasted effort.

## H. Defects in the collector that this capture exposed

Recorded here, in the reference document, because a tool's artefacts read exactly like the site's
properties once they are in a JSON file — and the next person to open this capture will not know
which is which unless it is written down.

**1. `paneOf()` is not per-pane.** All four `panes.*.panel` objects are deep-equal. The heading
lookup finds four distinct headings, but `closest('.panel, .card, .box, section, .well')` resolves
to the same shared ancestor for all of them. Roughly **17.7% of the 118,757-byte file is duplicated
content** as a result, and the per-pane structure the capture was meant to hold is absent.

**2. Silent truncation.** `html` is capped at exactly 4,000 characters and `text` at exactly 300,
with **no ellipsis and no marker**. A truncated field is indistinguishable from a complete one. This
is the same defect `collect-manage-gaps.js` was written to fix in its predecessor, and its header
calls silent truncation "the worst kind" of failure — reintroduced here.

**3. Every `styles.css` rule is stored twice** in every `rules` array, and no rule from
`bootstrap.min.css` ever appears. The duplication inflates the file; the absence means the Bootstrap
cascade is uncaptured.

**4. Headings carry no `rules` key at all** — `panel` and control nodes have 11 keys including
`rules`, the four `heading` objects have 10 and no `rules`. Heading CSS is therefore uncaptured, and
`withRules` was simply never passed for them.

**5. The five `refusedClicks` are tool behaviour, not a site property.** All five report
`matched: "New"`. The deny word `new` matched inside the handler expression
`showNewRoom=showNewRoom+1;` after camelCase splitting — the word does not occur in the label
`Sessions` at all. The New Room reveal never happened and its markup is missing from the capture.
Fixed in `dbc7001`; the exemption now short-circuits both guards.

**6. The redactor was provably inconsistent within a single field** — masking applied in one place
and not another a few characters away. Addressed by `4928f47`, which also masks by parameter NAME so
an unpredicted credential shape is still caught by its label.

**7. `provenance.userAgent` reports an Android Pixel 9 mobile Chrome while `provenance.viewport` is
1989 px wide.** Device emulation or a spoofed UA — worth knowing before treating any rect or
computed style here as desktop truth.

**8. `app.dashboard` and `app-dock.dashboard` both register the URL `/dashboard`** with the same
template. Not a collector defect — a genuine duplicate registration in the reference, recorded here
because it will look like a capture error otherwise.
