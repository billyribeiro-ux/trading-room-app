### 1.3 Findings fixed

**Stale verification claim — medium.** `docs/ENGINEERING-SSOT.md:352`,
`docs/PRODUCTION-CUTOVER-PLAN.md:86`, and two rows of
`docs/SVELTE-CONFORMANCE-AUDIT.md` each certified this branch's `pnpm quality`
as **89 Vitest tests** while the tree ran **108**. The arithmetic
`108 − 19 = 89` — 19 being the SQLite suite added by `0ed2faf` — proves the
pre-branch baseline was re-scoped onto the branch without re-running the gate.
That is the precise practice `AGENTS.md:43-44` prohibits.

Counts corrected, and a new gate now prevents recurrence:
`scripts/verify-documented-test-counts.mjs` (wired as `test:counts` inside the
`test` chain) measures the live suite through the Vitest JSON reporter and fails
on any stale documented figure. It was proved to fail against the original 89 and
pass at the measured value. Dated historical rows keep their own totals; the
verifier anchors on the ratcheted-threshold row so it never rewrites them.

**Two unproven guards — low.** Conformance section 15 asserted that owner
mismatch and non-canonical paths fail before a connection is returned. Neither
had a test, and three symlink tests used bare `.toThrow()` that would pass on any
error. Both guards now have focused tests, and both were **mutation-proved**:
deleting the storage-root uid comparison, or the trusted-parent
`realpathSync.native` comparison, fails exactly the corresponding test and
nothing else. The ancestor-symlink case is load-bearing because `O_NOFOLLOW`
rejects only a symlinked _final_ component, leaving that canonical comparison as
the sole defense against a symlinked ancestor.

**`MEDIA_BIND_ADDRESS` never validated — low.** `localhost:4443` is accepted by
`TcpListener::bind` via DNS but failed the separate `SocketAddr` parse that
decides the loopback-development exemption, so startup reported
`ConfigError::Invalid` against `MEDIA_ANNOUNCED_ADDRESS` — a variable whose value
was correct. The direction was already fail-closed: the parse could only withhold
the exemption, never grant it, so no admission or exposure boundary changed. This
was a diagnostic and validation defect, not a security one.
`Config::validate` now parses the bind address and rejects any non-`IP:port` form
under its own key before a worker is spawned. Mutation-proved: reverting the
validation reproduces the exact original misattribution.

**Gate-membership drift — low.** `backend:release:verify` and
`backend:migrations:verify` run inside `pnpm quality` through the `test` chain but
were documented as separate opt-in Rust commands. Both are now named on the
correct side of that line. The `backend:migrations:verify` omission predates this
branch.

### 1.4 Findings deliberately not acted on

Three findings were refuted with runtime evidence and left alone. Re-raising them
without new evidence would be re-litigating settled questions.

- The bare-`.toThrow()` sidecar tests **do** catch guard removal (proved by
  mutation).
- The second `repairExistingSqliteFiles` call is **not** a no-op on any non-empty
  database; the WAL pragma creates both sidecars before it runs.
- The in-archive `SHA256SUMS` manifest cannot resist an attacker who controls the
  archive; signing is already deferred to a separate promotion gate, so this is a
  documented boundary rather than a defect.

### 1.5 Honest gaps carried forward

The **file-level ownership branch remains untested**. The opener reads
`process.getuid` once and threads the value through, so a forged uid reaches the
directory guard first, and a genuinely foreign-owned file requires a privileged
`chown` that unprivileged CI cannot create. This is recorded in conformance
section 15 rather than covered by a test that would only appear to exercise it.

The `services/**` integrity seal moved with the source, as designed: files remain
**93**, the path list is unchanged, and the content manifest advanced to
